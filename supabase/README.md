# Supabase 닉네임 랭킹 연결

기존 꼬박게임 프로젝트 https://lzhphyellvrprptndpfc.supabase.co 를 사용합니다. 로그인이나 Supabase Auth 설정은 필요하지 않습니다. 닉네임 저장 버튼과 별도 닉네임 등록 과정은 없으며, 게임 시작 시 입력한 이름을 브라우저가 기억합니다.

## 설치와 기존 프로젝트 변경

1. 기존 프로젝트의 **SQL Editor → New query**에서 [schema.sql](schema.sql) **전체를 실행**합니다. 새 설치와 기존 3개 테이블 구조의 변경 모두 같은 파일을 사용합니다. 이전 `nickname-rules.sql`은 이번 구조 변경에 사용하지 않습니다.
2. 게임을 새로고침하고 닉네임을 입력합니다.
3. 전체 14앨범 코스를 완주하면 주간·전체·개인 기록에 반영됩니다. 선택 앨범 연습은 온라인 요청 없이 이 기기에만 기록합니다.

SQL은 하나의 트랜잭션으로 실행하며 재실행할 수 있습니다. 현재 `fromis_nickname_runs`의 **기존 완료·미완료 행과 기록 ID를 모두 보존**하고, 사용하지 않는 4개 컬럼과 `fromis_nickname_profiles`, `fromis_courses` 테이블을 제거합니다. 과거 Auth 방식의 `fromis_runs`가 코스 표를 참조하면 그 연결 제약만 제거하며 역사 기록은 유지합니다. 모든 `kkobak_*` 객체는 변경하지 않습니다. 예상하지 못한 다른 종속 객체가 있으면 `CASCADE`로 지우지 않고 전체 변경이 실패하도록 구성했습니다.

## 현재 사용하는 기록 테이블

활성 랭킹은 **`public.fromis_nickname_runs` 하나**를 사용합니다.

| 컬럼 | 용도 |
|---|---|
| `id` | 판별 UUID. 완주 전에는 해당 판을 제출하는 비공개 값 |
| `nickname` | 플레이한 닉네임 |
| `course_version` | 곡 목록이 다른 코스의 기록을 구분하는 버전 |
| `device` | `pc` 또는 `mobile` |
| `started_at` | 서버 시작 시각. 제출 시간 범위 검사에 사용 |
| `finished_at` | 서버 완주 시각. 미완주 상태는 `null` |
| `elapsed_ms` | 일시정지를 제외한 플레이 시간 |
| `cpm` | 서버가 계산한 분당 타수 |
| `accuracy` | 서버가 계산한 정확도 |

앨범 목록은 시작 함수가 전체 순서와 일치하는지 확인하고 저장하지 않습니다. 입력 정답·시도 타수도 완주 함수의 인자로 검증하고 CPM·정확도를 계산한 뒤 별도 컬럼에 저장하지 않습니다. 별도의 `finish_token` 컬럼은 없습니다.

## 닉네임 규칙

앞뒤 공백 제거와 NFC 정규화 뒤 **초성·숫자·ASCII 특수기호 1~6글자**를 허용합니다. 쌍자음 초성과 현대 초성 자모(`ᄀ`~`ᄒ`)도 사용할 수 있습니다. 영문·완성형 한글·모음·겹받침·내부 공백·이모지는 제외합니다. `<`, `>`도 허용하며 화면에는 텍스트로 표시합니다.

허용식은 `^[ㄱㄲㄴㄷㄸㄹㅁㅂㅃㅅㅆㅇㅈㅉㅊㅋㅌㅍㅎᄀ-ᄒ\x21-\x40\x5b-\x60\x7b-\x7e]{1,6}$`이며 SQL은 `COLLATE "C"`로 검사합니다. 새 `NOT VALID` 제약은 기존 이름을 변경하거나 지우지 않으면서 신규·수정 행에 현재 규칙을 적용합니다. 기존 부적합 이름의 완료 기록도 랭킹에는 남습니다.

같은 닉네임은 누구나 같은 공개 기록을 조회하고 등록할 수 있습니다. 이름 소유권이나 계정은 없으며 닉네임을 바꾸면 별도의 이름으로 취급합니다. PC·모바일은 각각 구분합니다.

## 시작과 완주 검증

전체 코스의 시작 함수는 서버에 고정한 **코스 버전·14앨범의 ID와 순서·67곡**을 기준으로 요청을 확인한 뒤 한 행을 생성합니다. 현재 버전은 `fromis-full-nickname-v1-34b55b7a16952c88`이며 최소 입력량은 654타입니다. 향후 곡 목록이 바뀌면 `schema.sql` 안의 버전·앨범 배열·곡 수·최소 입력량과 클라이언트 설정을 함께 갱신해야 합니다. 코스 버전은 이전 기록과 재사용하지 않습니다.

시작 시 받은 `run_id`는 완주 전까지 메모리에만 보관하는 **제출용 비공개 값**입니다. 공개 랭킹·개인 조회 함수는 `finished_at is not null`인 기록만 반환합니다. 테이블은 RLS와 권한 회수로 직접 읽기·쓰기를 막고 전용 함수만 허용합니다.

완주 함수는 해당 행을 잠근 뒤 다음을 검사합니다.

- 현재 코스 버전과 완료 곡 수 67개
- 24시간의 제출 기한, 최대 활성 시간 4시간
- 최소 입력량 654타 기준 3,000타/분 이하인 입력량과 플레이 시간
- 정답 타수 이상인 시도 타수, 최대 시도 100,000타
- 서버 시작 시각보다 과도하게 긴 활성 시간

통과하면 서버 시각과 계산한 CPM·정확도를 저장합니다. 완료 행은 재제출해도 수정하지 않고 기존 결과를 반환합니다. 완료 ID는 공개해도 다시 기록을 바꿀 수 없습니다. 실제 키 입력을 서버에서 재생하는 구조는 아니므로 이 범위 검사가 완전한 부정행위 방지를 보장하지는 않습니다.

캐시된 이전 클라이언트를 위해 닉네임 검증만 하는 `fromis_nickname_set`과 이전 6인자 완주 함수는 호환용으로 유지합니다. 시작 응답의 `run_token`은 `run_id`와 같은 호환용 별칭이며 따로 저장하지 않습니다. 새 화면은 이 등록 함수와 토큰을 사용하지 않습니다.

## 순위와 공개 연결

주간은 최근 7일, 전체는 해당 코스 버전의 모든 완료 기록입니다. PC·모바일별로 같은 닉네임의 가장 빠른 한 기록을 표시합니다. 동률이면 정확도·완주 시각·ID 순서입니다. 개인 기록은 해당 이름의 최고 기록과 최근 완료 기록을 조회합니다.

`dist/data/ranking-config.json`에는 기존 프로젝트의 공개 publishable 키만 사용합니다. `sb_secret_` 또는 `service_role` 키는 프런트에서 거부합니다. 사용자 생성·로그인·JWT 저장은 하지 않습니다.

이번 파일은 로컬에서 정적 검사를 거쳤습니다. 실제 Supabase에는 사용자가 SQL을 실행한 뒤 공개 API로 연결과 규칙을 확인해야 합니다.
