# Supabase 완주 기록 연결

기존 꼬박게임 프로젝트 https://lzhphyellvrprptndpfc.supabase.co 를 사용합니다. 로그인이나 Supabase Auth 설정은 필요하지 않습니다. 닉네임은 브라우저가 자동으로 기억하며, 게임을 시작할 때 서버 요청이나 미완료 행을 만들지 않습니다. 전체 코스를 완주했을 때만 기록을 한 번 제출합니다.

## 설치와 기존 프로젝트 변경

1. 기존 프로젝트의 **SQL Editor → New query**에서 [schema.sql](schema.sql) **전체를 실행**합니다. 새 설치와 기존 9개 컬럼 구조 변경 모두 같은 파일을 사용합니다.
2. 게임을 새로고침하고 닉네임을 입력해 플레이합니다.
3. 전체 14앨범·67곡을 완주하면 주간·전체·개인 기록에 반영됩니다. 선택 앨범 연습은 이 기기에만 기록합니다.

SQL은 한 트랜잭션으로 실행하며 재실행할 수 있습니다. 기존 `fromis_nickname_runs`의 **완료 행과 기록 ID는 모두 보존**합니다. 이전 시작 요청인 `finished_at IS NULL` 행만 제거하고, `course_version`, `started_at`과 예전 불필요한 컬럼을 제거합니다. 이전 시작·닉네임 등록·완주 함수도 제거하여 캐시된 화면이 새 미완료 행을 만들 수 없게 합니다.

3개 테이블을 쓰던 프로젝트도 같은 SQL로 변경할 수 있습니다. 현재 닉네임 기록과 과거 Auth 기록에서 폐기할 표를 가리키는 연결 제약만 해제하고, `fromis_nickname_profiles`, `fromis_courses`를 제거합니다. 과거 Auth 방식의 기록 행과 모든 `kkobak_*` 객체는 변경하지 않습니다. 예상하지 못한 다른 종속 객체가 있으면 `CASCADE`로 지우지 않고 전체 변경이 실패하도록 구성했습니다.

## 기록 테이블

활성 랭킹은 **`public.fromis_nickname_runs` 하나, 7개 컬럼**을 사용합니다.

| 컬럼 | 용도 |
|---|---|
| `id` | 클라이언트가 완주 시 생성한 UUID. 같은 결과의 재시도에 동일 ID 사용 |
| `nickname` | 플레이한 닉네임 |
| `device` | `pc` 또는 `mobile` |
| `finished_at` | 최초 저장 시 서버가 기록한 완주 시각 |
| `elapsed_ms` | 카운트다운 종료부터 완주까지 경과한 시간 |
| `cpm` | 서버가 계산한 분당 타수 |
| `accuracy` | 서버가 계산한 정확도 |

일시정지 기능은 없습니다. 게임 중 탭을 떠나거나 안내·확인창을 열어도 시간이 계속 흐릅니다. 시작 시각과 코스 버전은 서버에 저장하지 않으며, 기록 조회도 버전을 구분하지 않습니다. 클라이언트의 곡 목록 해시는 현재 목록과 설정의 일치 확인에 사용합니다.

## 닉네임 규칙

앞뒤 공백 제거와 NFC 정규화 뒤 **초성·숫자·ASCII 특수기호 1~6글자**를 허용합니다. 쌍자음 초성과 현대 초성 자모(`ᄀ`~`ᄒ`)도 사용할 수 있습니다. 영문·완성형 한글·모음·겹받침·내부 공백·이모지는 제외합니다. `<`, `>`도 허용하며 화면에는 텍스트로 표시합니다.

허용식은 `^[ㄱㄲㄴㄷㄸㄹㅁㅂㅃㅅㅆㅇㅈㅉㅊㅋㅌㅍㅎᄀ-ᄒ\x21-\x40\x5b-\x60\x7b-\x7e]{1,6}$`입니다. SQL은 `COLLATE "C"`로 검사합니다. `NOT VALID` 제약은 기존 완료 이름과 값을 변경하거나 지우지 않으면서 새 기록에 현재 규칙을 적용합니다. 기존 부적합 이름의 완료 기록도 랭킹에 남습니다.

같은 닉네임은 누구나 같은 공개 기록을 조회하고 등록할 수 있습니다. 이름 소유권이나 계정은 없으며 닉네임을 바꾸면 별도의 이름으로 취급합니다. PC·모바일은 각각 구분합니다.

## 완주 시 한 번 제출

프런트는 완주 결과의 UUID와 닉네임·기기·앨범 목록·완료 곡 수·플레이 시간·정답/시도 타수를 `fromis_nickname_submit`으로 보냅니다. 같은 결과를 재시도할 때 결과 UUID를 다시 만들지 않습니다.

서버는 고정된 **14앨범 ID와 순서·67곡·최소 입력량 654타**를 확인합니다. 최대 플레이 시간 4시간, 최대 입력 시도 100,000타, 분당 3,000타 이하의 시간·입력량 범위도 검사하고 CPM·정확도를 계산합니다. 앨범 목록과 입력 카운터는 검사에만 사용하고 저장하지 않습니다. 서버 시작 요청이 없으므로 서버 시작 시각과의 시간 비교는 하지 않습니다.

검사를 통과하면 서버 시각으로 한 행을 INSERT합니다. 같은 ID와 저장 결과가 이미 있으면 기존 결과를 반환합니다. 같은 ID에 다른 닉네임·기기·시간·타수·정확도를 보내면 거부하며, 기존 행을 UPDATE하지 않습니다. 테이블은 RLS와 권한 회수로 직접 읽기·쓰기를 막고 전용 함수만 허용합니다.

## 순위와 공개 연결

주간은 최근 7일, 전체는 모든 완료 기록입니다. PC·모바일별로 같은 닉네임의 가장 빠른 한 기록을 표시합니다. 동률이면 정확도·완주 시각·ID 순서입니다. 개인 기록은 해당 이름의 최고 기록과 최근 완료 기록을 조회합니다.

API는 다음 세 가지입니다.

- `fromis_nickname_submit(p_id, p_nickname, p_device, p_album_ids, p_completed_track_count, p_elapsed_ms, p_correct_strokes, p_attempted_strokes)`
- `fromis_nickname_leaderboard(p_period, p_device, p_limit, p_nickname)`
- `fromis_nickname_personal(p_device, p_nickname)`

`dist/data/ranking-config.json`에는 기존 프로젝트의 공개 publishable 키만 사용합니다. `sb_secret_` 또는 `service_role` 키는 프런트에서 거부합니다. 사용자 생성·로그인·JWT 저장은 하지 않습니다.

이번 SQL은 로컬에서 정적 검사를 거쳤습니다. 사용자가 실제 Supabase에 실행한 뒤 공개 API로 조회와 규칙을 확인해야 합니다.
